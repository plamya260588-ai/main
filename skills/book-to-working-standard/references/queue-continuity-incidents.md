# Инциденты непрерывности пакетной очереди

Использовать только при пакетной обработке книг. Это фактическая память о сбоях, исправленных 24 сентября 2026 года.

## Зафиксированные случаи

1. После создания *Team Topologies* агент объявил, что очередь переключена на *Slow Productivity*, но завершил ход, не начав чтение следующего источника. Пользователю пришлось написать «продолжай».
2. После создания *Slow Productivity* файл и копия в библиотеке существовали, но реестр оставался `in progress`, а каталог не содержал записи. Это рассинхрон публикационной транзакции.
3. После создания *Психологии счастья* агент сохранил файл и завершил ответ, не обновив каталог, статус `complete`, следующую позицию и checkpoint.
4. Периодическая automation первоначально была поставлена на час; затем на 5 минут. Она не обеспечила немедленный переход, потому что основной агент закрывал ход до старта следующего источника.
5. Prompt automation запрещал промежуточные сообщения, поэтому пользователь не видел отсутствие checkpoint и был вынужден диагностировать процесс вручную.

## Корневой инвариант

Ни publish, ни `complete`, ни `in progress` по отдельности не означают непрерывность. Непрерывность существует только когда в одном ходе выполнена цепочка:

`verified standard → library copy → catalog → complete → next in progress → source checkpoint`.

Любая остановка до последнего элемента считается незавершённой очередью, а не нормальным финалом ответа.
